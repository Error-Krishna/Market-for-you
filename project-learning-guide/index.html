What is Market Aura 4U?

Product Definition

Market Aura 4U is an AI-powered social media management and marketing SaaS platform engineered for brands, digital marketing agencies, solo founders, and content creators. It automates the complete lifecycle of social media marketing: from intelligent brand voice onboarding, to audience-grounded AI generation with Groq LLaMA 3.3 and Python ML algorithms, to Cloudflare R2 media management, automated calendar scheduling with distributed lease locking, and direct verified publishing to Instagram Business and X/Twitter.

The Core Problem It Solves:

Modern creators and businesses currently juggle 4–6 fragmented tools: ChatGPT for raw un-grounded text, Canva for slides, Dropbox for asset storage, Buffer or Hootsuite for scheduling, and Stripe for payments. This results in generic AI copy that ignores brand tone, manual copy-pasting, disconnected media hosting, and expensive multi-tool subscription fees. Market Aura 4U consolidates this entire pipeline into one unified system.

Intended Users

Small business owners, digital marketing agencies, solo creators, and SaaS growth teams.

Core Feedback Loop

Onboard Brand → ML Audience Grounding → Groq LLaMA Generation → Review/Edit → Schedule / Verified Publish.

Layered Microservices vs Monolith — 7-Point Architectural Breakdown

Implementation Deep-Dive
1. What is it?

The Core Definition

An architectural pattern that divides a system into decoupled services: React SPA for reactive UI, Express 5 for fast async API coordination, and Python for compute-heavy ML.

2. Why do we need it?

The Problem Solved

Without separation, running heavy Python Sentence-Transformers and XGBoost models in Node.js would block the event loop and crash web requests.

3. How Market Aura Uses It

Project Implementation

Market Aura 4U runs Node.js on port 8000 and Python ML on port 8080 connected via Docker bridge networking.

4. Where is it located?

Concrete Source File

market-aura-4u-backend-main/src/app.js & CAPSTONE/src/serve.py

5. How it works internally

Execution Flow

Browser -> Nginx -> Express API (JWT verify) -> Python ML HTTP fetch (5s timeout) -> Groq LLM -> Response.

6. What happens if it fails?

Failure Scenarios & Recovery

If Python ML fails, recommenderClient.js catches the timeout and falls back to brand profile heuristics without breaking generation.

7. Interview Gold — How to explain this to an interviewer

The Senior Engineering Answer

Explain that separating CPU-bound machine learning from I/O-bound web APIs prevents event loop starvation and provides independent horizontal scaling.

Architectural Boundaries & Data Flow Principles

System Design

1. Client to API (JWT / CORS)

React 19 SPA communicates over Axios HTTP. Tokens are transmitted via both HTTP-only cookies and Authorization Bearer headers. Dynamic CORS whitelist validates origin requests.

2. API to ML Recommender (HTTP :8080)

Internal container communication on port 8080. Recommender client enforces a 5,000ms AbortSignal timeout and graceful fallback if the Python service is offline.

3. API to MongoDB (Mongoose Pool)

Persistent Mongoose connection with maxPoolSize: 20 and serverSelectionTimeoutMS: 5000ms, preventing Atlas M0 connection pool exhaustion during concurrent operations.

4. API to External Services (R2 & Meta)

Media is stored in Cloudflare R2 and served via public HTTPS CDN URLs, which Meta Graph API v21.0 requires for container ingestion during automated publishing.

Server Initialization Lifecycle (src/app.js)

Startup Sequence

When node src/app.js executes, it executes the following strict order of operations:

  1. CORS Initialization: createCorsMiddleware() configures dynamic origin allowlists with credentials support.
  2. IP Rate Limiting: limitAuthIp restricts brute-force attempts on /api/v1/auth.
  3. Body Parsers with Scoped Limits: Express JSON parser with 15mb payload strictly for /api/v1/media (image/video base64 uploads) and 100kb for standard routes.
  4. Probes: /health (status: ok) and /ready (verifies mongoose.connection.readyState === 1).
  5. Router Mounting: Mounts apiRouter at /api → /v1.
  6. Database & Scheduler Startup: Listens on port 3000/8000, connects to MongoDB via connectDB(), and starts startScheduler() (polling every 15s).
  7. Graceful Shutdown: Listens for SIGINT and SIGTERM, stops the scheduler timer, closes the HTTP server, and exits cleanly.

Fail-Fast Production Secret Resolution

Security Hardening

In src/utils/tokenCrypto.js, secret resolution functions enforce a fail-fast policy in production:

if (NODE_ENV === 'production' && !secret) {
  throw new Error('JWT_SECREAT_KEY or JWT_SECRET_KEY environment variable is required in production.');
}

This guarantees that a production server will never start with fallback development keys or placeholder encryption strings (like 0000000000000000...).

SocialAccount (SocialAccount.js)

  • • userId: ObjectId → User
  • • provider: 'instagram' | 'twitter' | 'linkedin' | 'facebook'
  • • providerAccountId: String (external account ID)
  • • encryptedAccessToken: AES-256-GCM (select: false)
  • • encryptedRefreshToken: AES-256-GCM (select: false)
  • • Index: { userId: 1, provider: 1, providerAccountId: 1 } (unique)

OAuthState (OAuthState.js)

  • • state: String (24-byte hex, unique)
  • • userId: ObjectId → User
  • • platform: String
  • • expiresAt: Date (now + 10 min)
  • • TTL Index: { expires: 0 } auto-deletes expired documents

OAuth 2.0 PKCE State Architecture (CSRF Protection)

PKCE Flow

Connecting third-party social accounts (Instagram, Twitter, LinkedIn) follows a strict PKCE flow to prevent Cross-Site Request Forgery (CSRF):

  1. User clicks "Connect Instagram" → API generates a cryptographically random 24-byte hex state: crypto.randomBytes(24).toString('hex').
  2. Stores state in OAuthState collection with userId and expiresAt: now + 10min.
  3. Redirects user to Meta's authorization URL with state parameter.
  4. On callback, backend executes OAuthState.findOneAndDelete({ state, platform }). If not found or expired, request is rejected immediately.
  5. Exchange code for access token, encrypt with AES-256-GCM, and save to SocialAccount.

// 1. Atomic Lease Claim: exactly one server instance acquires lock
async function claimDuePost(now, workerId) {
  return ScheduledPost.findOneAndUpdate(
    {
      deliveryOutcomeUnknown: { $ne: true },
      $and: [
        { status: 'scheduled', scheduledAt: { $lte: now } },
        { $or: [{ lockUntil: null }, { lockUntil: { $lte: now } }] },
      ],
    },
    {
      $set: {
        status: 'processing',
        lockUntil: new Date(now.getTime() + LOCK_DURATION_MS), // 120s lease
        lockedBy: workerId,
        lastRunAt: now,
      },
      $inc: { __v: 1 }, // Optimistic concurrency version bump
    },
    { sort: { scheduledAt: 1 }, new: true }
  );
}

// 2. Crash Recovery: Sweeps expired leases to prevent blind double-publishing
async function markOutcomeUnknown(filter) {
  return ScheduledPost.updateMany(
    filter,
    [{ $set: {
      status: 'failed', lockUntil: null, lockedBy: null, nextRetryAt: null,
      deliveryOutcomeUnknown: true,
      platforms: { $map: { input: '$platforms', as: 'entry', in: {
        $cond: [
          { $in: ['$$entry.status', ['pending', 'processing']] },
          { $mergeObjects: ['$$entry', { status: 'failed', outcomeUnknown: true, 
            lastError: 'Delivery outcome unknown after worker interruption.' }] },
          '$$entry',
        ],
      } } },
    } }]
  );
}

// Zero-Trust Authenticated Symmetric Token Encryption
function encryptSecret(plaintext) {
  if (typeof plaintext !== 'string' || plaintext.length === 0) return null;
  const key = resolveEncryptionKey();
  const iv = crypto.randomBytes(12); // Randomized 12-byte initialization vector
  const cipher = crypto.createCipheriv('aes-256-gcm', key, iv);
  const encrypted = Buffer.concat([cipher.update(plaintext, 'utf8'), cipher.final()]);
  const tag = cipher.getAuthTag(); // 16-byte authentication tag detects tampering
  return `${iv.toString('base64url')}.${tag.toString('base64url')}.${encrypted.toString('base64url')}`;
}

// SSRF Defense: Blocks internal subnets, loopbacks, and AWS/GCP metadata
function isPrivateOrLoopbackHost(hostname) {
  const lower = String(hostname || '').toLowerCase();
  if (lower === 'localhost' || lower.endsWith('.internal') || lower.endsWith('.local')) return true;
  const ipVersion = net.isIP(lower);
  if (ipVersion === 4) {
    const parts = lower.split('.').map(Number);
    if (parts[0] === 10 || parts[0] === 127 || parts[0] === 0) return true; // 10.x, 127.x
    if (parts[0] === 169 && parts[1] === 254) return true; // Cloud metadata: 169.254.x.x
    if (parts[0] === 172 && parts[1] >= 16 && parts[1] <= 31) return true; // 172.16-31.x
    if (parts[0] === 192 && parts[1] === 168) return true; // 192.168.x
  }
  return false;
}
